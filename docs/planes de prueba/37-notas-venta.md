# Plan de pruebas: Notas de venta

- **Menú:** Ventas y caja → Notas de venta.
- **Ruta:** `/notas-venta`.
- **Permiso de navegación:** `nav.notas_venta`. Verificar además permisos de operación; mostrar el menú no autoriza toda escritura.
- **Fecha de revisión del código:** 2026-09-20.
- **Estado inicial:** todos los casos pendientes; este documento no acredita ejecución.
- **Guía obligatoria:** [criterios comunes](00-criterios-comunes.md), [flujos integrales](00-flujos-integrales.md) e [índice](README.md).

## Preparación y registro

Usar entorno QA con tenant A, tenant B, dos establecimientos de A y usuarios autorizado, lector y sin permiso. Preparar datos `QA-notas-venta-*`, conjunto vacío, una fila y más de dos páginas cuando exista listado. Registrar versión de frontend/API, fecha, navegador, viewport, rol, tenant y establecimiento. No usar datos personales reales ni enviar comprobantes de prueba a producción.

Marcar cada casilla al **ejecutar** el caso, no al darlo por aprobado. Añadir `Resultado: PASÓ / FALLÓ / BLOQUEADO / N/A; evidencia: …; incidencia: …`. N/A exige motivo y validación; un control ausente que se esperaba no se da por aprobado. Cada variante de un caso se registra por separado.

## Pantalla y controles identificados

Etiquetas observadas: `Desde`, `Hasta`, `Comprobante destino`, `Motivo`, `Descripción en comprobante`, `Monto total (inc. IGV)`.

Botones/textos observados: `Ver`, `PDF`, `Emitir a SUNAT`, `Migrar a boleta/factura`, `Devolver`, `Nota de débito`, `Reintentar`, `Descargar PDF`, `Devolver productos`, `Cancelar`, `{{ convertMutation.isPending() ? 'Migrando…' : 'Migrar y emitir' }}`, `Confirmar devolución`, `Emitir ND`. Los textos con interpolaciones se contrastan con su valor visible durante ejecución.
