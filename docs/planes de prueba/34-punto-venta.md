# Plan de pruebas: Punto de venta

- **Menú:** Ventas y caja → Punto de venta.
- **Ruta:** `/punto-venta`.
- **Permiso de navegación:** `nav.punto_venta`. Verificar además permisos de operación; mostrar el menú no autoriza toda escritura.
- **Fecha de revisión del código:** 2026-09-20.
- **Estado inicial:** todos los casos pendientes; este documento no acredita ejecución.
- **Guía obligatoria:** [criterios comunes](00-criterios-comunes.md), [flujos integrales](00-flujos-integrales.md) e [índice](README.md).

## Preparación y registro

Usar entorno QA con tenant A, tenant B, dos establecimientos de A y usuarios autorizado, lector y sin permiso. Preparar datos `QA-punto-venta-*`, conjunto vacío, una fila y más de dos páginas cuando exista listado. Registrar versión de frontend/API, fecha, navegador, viewport, rol, tenant y establecimiento. No usar datos personales reales ni enviar comprobantes de prueba a producción.

Marcar cada casilla al **ejecutar** el caso, no al darlo por aprobado. Añadir `Resultado: PASÓ / FALLÓ / BLOQUEADO / N/A; evidencia: …; incidencia: …`. N/A exige motivo y validación; un control ausente que se esperaba no se da por aprobado. Cada variante de un caso se registra por separado.

## Flujos específicos y reglas de negocio

- [ ] **M34-NEG-01 — Venta contado completa (P1; P0 si afecta stock, dinero o aislamiento).**
  - **Pasos y datos:** Abrir caja propia; elegir almacén de sucursal, cliente, producto, documento y serie; cobrar exacto y con vuelto.
  - **Esperado:** Venta única, total correcto, pago registrado, stock descontado y ticket/PDF recuperable.
  - **Resultado / evidencia / incidencia:** pendiente.

- [ ] **M34-NEG-02 — Carrito y presentaciones (P1; P0 si afecta stock, dinero o aislamiento).**
  - **Pasos y datos:** Agregar por búsqueda/escáner, repetir producto, sumar/restar, quitar y vaciar; usar pack y servicio.
  - **Esperado:** Cantidades y totales consistentes; servicio no altera stock y pack consume sus componentes.
  - **Resultado / evidencia / incidencia:** pendiente.

- [ ] **M34-NEG-03 — Stock y concurrencia (P1; P0 si afecta stock, dinero o aislamiento).**
  - **Pasos y datos:** Intentar vender cero, negativo y más stock; dos cajeros venden la última unidad simultáneamente.
  - **Esperado:** No hay sobreventa no autorizada; una operación rechazada no cobra ni deja movimientos parciales.
  - **Resultado / evidencia / incidencia:** pendiente.

- [ ] **M34-NEG-04 — Lotes y receta (P1; P0 si afecta stock, dinero o aislamiento).**
  - **Pasos y datos:** Elegir lotes manual/automático, vencido y agotado; seleccionar receta y validación manual con distintos permisos.
  - **Esperado:** Se respeta disponibilidad, regla de asignación y control de receta; no se evade por API.
  - **Resultado / evidencia / incidencia:** pendiente.

- [ ] **M34-NEG-05 — Sustitución (P1; P0 si afecta stock, dinero o aislamiento).**
  - **Pasos y datos:** Seleccionar sustituto, cambiar cantidad y cobrar; revisar producto original y sustituto en detalle.
  - **Esperado:** Precio y stock corresponden a lo entregado; se conserva referencia de sustitución.
  - **Resultado / evidencia / incidencia:** pendiente.

- [ ] **M34-NEG-06 — Pagos mixtos y crédito (P1; P0 si afecta stock, dinero o aislamiento).**
  - **Pasos y datos:** Combinar efectivo y otro medio, agregar/quitar líneas, completar saldo restante; probar pago insuficiente y crédito.
  - **Esperado:** Suma de pagos, vuelto y saldo pendiente correctos; crédito genera CxC una sola vez.
  - **Resultado / evidencia / incidencia:** pendiente.

- [ ] **M34-NEG-07 — UI móvil y teclado (P1; P0 si afecta stock, dinero o aislamiento).**
  - **Pasos y datos:** Alternar Catálogo/Carrito a 390 px; usar F2 y escáner; cobrar con teclado virtual visible.
  - **Esperado:** Carrito persiste; hay un único Cobrar operativo y no se duplica la venta por tecla/clic.
  - **Resultado / evidencia / incidencia:** pendiente.

- [ ] **M34-NEG-08 — Pérdida de respuesta (P1; P0 si afecta stock, dinero o aislamiento).**
  - **Pasos y datos:** Cortar conexión durante cobro, consultar si existe venta antes de reintentar, reimprimir y descargar último PDF.
  - **Esperado:** Reimpresión no cobra de nuevo; estado recuperable sin duplicar stock/pagos.
  - **Resultado / evidencia / incidencia:** pendiente.
