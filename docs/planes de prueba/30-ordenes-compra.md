# Plan de pruebas: Órdenes de compra

- **Menú:** Compras → Órdenes de compra.
- **Ruta:** `/ordenes-compra`.
- **Permiso de navegación:** `nav.ordenes_compra`. Verificar además permisos de operación; mostrar el menú no autoriza toda escritura.
- **Fecha de revisión del código:** 2026-09-20.
- **Estado inicial:** todos los casos pendientes; este documento no acredita ejecución.
- **Guía obligatoria:** [criterios comunes](00-criterios-comunes.md), [flujos integrales](00-flujos-integrales.md) e [índice](README.md).

## Preparación y registro

Usar entorno QA con tenant A, tenant B, dos establecimientos de A y usuarios autorizado, lector y sin permiso. Preparar datos `QA-ordenes-compra-*`, conjunto vacío, una fila y más de dos páginas cuando exista listado. Registrar versión de frontend/API, fecha, navegador, viewport, rol, tenant y establecimiento. No usar datos personales reales ni enviar comprobantes de prueba a producción.

Marcar cada casilla al **ejecutar** el caso, no al darlo por aprobado. Añadir `Resultado: PASÓ / FALLÓ / BLOQUEADO / N/A; evidencia: …; incidencia: …`. N/A exige motivo y validación; un control ausente que se esperaba no se da por aprobado. Cada variante de un caso se registra por separado.

## Pantalla y controles identificados

Etiquetas observadas: la pantalla usa controles inline o componentes con etiquetas dinámicas; ver los campos y acciones siguientes.

Botones/textos observados: `Nueva OC`, `Buscar`, `{{ item.nombre }} · {{ item.codigoInterno }}`, `Crear OC`, `Aprobar`, `Anular`, `Enviar`. Los textos con interpolaciones se contrastan con su valor visible durante ejecución.

## Flujos específicos y reglas de negocio

- [ ] **M30-NEG-01 — Orden completa (P1; P0 si afecta stock, dinero o aislamiento).**
  - **Pasos y datos:** Crear orden con proveedor válido y dos productos; modificar cantidad/costo; guardar, aprobar y enviar.
  - **Esperado:** Totales y estados reflejan cada transición; la orden enviada está disponible en recepción.
  - **Resultado / evidencia / incidencia:** pendiente.

- [ ] **M30-NEG-02 — Transiciones inválidas (P1; P0 si afecta stock, dinero o aislamiento).**
  - **Pasos y datos:** Enviar sin aprobar, repetir aprobación/envío y operar una orden cancelada mediante API.
  - **Esperado:** Servidor rechaza transiciones no permitidas y no crea recepciones duplicadas.
  - **Resultado / evidencia / incidencia:** pendiente.

- [ ] **M30-NEG-03 — Saldo pendiente (P1; P0 si afecta stock, dinero o aislamiento).**
  - **Pasos y datos:** Recibir parcialmente desde Recepción mercadería y volver a la orden.
  - **Esperado:** Cantidades pedida, recibida y pendiente concilian por línea sin cerrar anticipadamente.
  - **Resultado / evidencia / incidencia:** pendiente.
