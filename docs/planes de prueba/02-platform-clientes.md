# Plan de pruebas: Clientes SaaS

- **Menú:** Plataforma → Clientes SaaS.
- **Ruta:** `/platform/clientes`.
- **Permiso de navegación:** `nav.platform_clientes`. Verificar además permisos de operación; mostrar el menú no autoriza toda escritura.
- **Fecha de revisión del código:** 2026-09-20.
- **Estado inicial:** todos los casos pendientes; este documento no acredita ejecución.
- **Guía obligatoria:** [criterios comunes](00-criterios-comunes.md), [flujos integrales](00-flujos-integrales.md) e [índice](README.md).

## Preparación y registro

Usar entorno QA con tenant A, tenant B, dos establecimientos de A y usuarios autorizado, lector y sin permiso. Preparar datos `QA-platform-clientes-*`, conjunto vacío, una fila y más de dos páginas cuando exista listado. Registrar versión de frontend/API, fecha, navegador, viewport, rol, tenant y establecimiento. No usar datos personales reales ni enviar comprobantes de prueba a producción.

Marcar cada casilla al **ejecutar** el caso, no al darlo por aprobado. Añadir `Resultado: PASÓ / FALLÓ / BLOQUEADO / N/A; evidencia: …; incidencia: …`. N/A exige motivo y validación; un control ausente que se esperaba no se da por aprobado. Cada variante de un caso se registra por separado.

## Pantalla y controles identificados

Etiquetas observadas: la pantalla usa controles inline o componentes con etiquetas dinámicas; ver los campos y acciones siguientes.

Botones/textos observados: `Nuevo cliente`, `Cancelar`, `{{ submitLabel() }}`. Los textos con interpolaciones se contrastan con su valor visible durante ejecución.

  - **Esperado:** Filtros y edición conservan el valor; restricciones del plan y suspensión se aplican también por API.
  - **Resultado / evidencia / incidencia:** pendiente.

- [ ] **M02-NEG-03 — Aprovisionamiento repetido o interrumpido (P1; P0 si afecta stock, dinero o aislamiento).**
